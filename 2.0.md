## 1. Ringkasan Eksekutif
SPPG Curug Cukanggalih 02 mengelola relawan yang terbagi dalam beberapa **divisi** (Pengolahan, Distribusi, Administrasi, dll). Saat ini, absensi dilakukan secara manual sehingga rawan praktik "titip absen", manipulasi jam kerja, dan lambatnya rekapitulasi honor bulanan.

Proyek ini membangun aplikasi web absensi dan penggajian (payroll) otomatis berbasis **Laravel 12**. Untuk mengatasi keterbatasan *Shared Hosting*, sistem ini mengintegrasikan **ARSA Face API** (verifikasi wajah & *liveness*) dan **Fonnte API** (notifikasi WhatsApp) sebagai layanan pihak ketiga (Cloud API) yang gratis. 

Sistem menjamin validitas kehadiran melalui 3 lapis keamanan: **Verifikasi Wajah**, **Geofencing (Haversine Formula)**, dan **Watermark Foto (Timestamp Server + GPS)**. Data kehadiran ini kemudian dikalkulasi secara otomatis menjadi slip gaji digital.

---

## 2. Latar Belakang & Masalah
1. **Titip Absen:** Kehadiran manual dapat diwakilkan oleh rekan kerja.
2. **Manipulasi Lokasi & Waktu:** Relawan bisa absen dari rumah atau memundurkan jam absen.
3. **Rekap Honor Manual:** Menghitung jam kerja 50+ relawan per bulan memakan waktu dan rawan *human error*.
4. **Tidak Ada Bukti Visual:** Tidak ada dokumentasi foto yang memuat waktu dan lokasi secara permanen untuk audit.
5. **Keterbatasan Dana Server:** Tidak ada anggaran untuk menyewa VPS atau API berbayar.

## 3. Ruang Lingkup (Scope)

### 3.1 In-Scope
- **Autentikasi & Otorisasi:** Laravel Sanctum (Role: Super Admin, Admin, Relawan).
- **Manajemen Divisi:** Pengaturan jam kerja per divisi (bukan shift).
- **Absensi Multi-Lapis:** Verifikasi Wajah (ARSA API) + Geofencing (Haversine) + Timestamp Server.
- **Watermark Server-Side:** Foto absensi dicap dengan Nama, NIK, Divisi, Jam Server, dan Koordinat GPS menggunakan `Intervention Image`.
- **Modul Izin/Cuti:** Relawan dapat mengunggah surat izin/sakit, Admin menyetujui.
- **Payroll Otomatis:** Generate honor, slip PDF (DomPDF), ekspor Excel.
- **Notifikasi WA:** Menggunakan Fonnte API (Pengingat absen, info slip gaji, alert admin).
- **Dashboard:** Statistik kehadiran dan *log* anomali (Fraud Detection).

### 3.2 Out-of-Scope
- Aplikasi Mobile Native (Android/iOS).
- Mode Offline.
- Integrasi mesin Fingerprint/Face ID fisik.

## 5. Kebutuhan Fungsional (Functional Requirements)

### 5.1 Autentikasi & Pengaturan Awal
- **F-01**: Login menggunakan Email & Password via Laravel Sanctum.
- **F-02**: Super Admin dapat mengatur Koordinat SPPG (Lat/Lng) dan Radius Geofencing di halaman Pengaturan.

### 5.2 Manajemen Divisi & Relawan
- **F-03**: Admin/Super Admin dapat mengelola Data Divisi (Tambah/Edit/Hapus).
- **F-04**: Admin/Super Admin dapat mengatur jam masuk & pulang untuk tiap divisi di tabel `work_schedules`.
- **F-05**: Admin/Super Admin dapat mendaftarkan Relawan baru, mengisi Nomor HP (untuk WA), dan menempatkannya ke Divisi tertentu.

### 5.3 Pendaftaran Wajah (Enrollment)
- **F-06**: Relawan wajib mengambil foto wajah pertama kali login.
- **F-07**: Laravel mengirim foto ke ARSA API untuk mengekstrak `face_id` dan menyimpannya di tabel `users`.

### 5.4 Proses Absensi (Masuk & Pulang)
- **F-08**: Klien mengambil *snapshot* wajah dan koordinat GPS via browser.
- **F-09**: Sistem menghitung jarak relawan ke SPPG dengan **Haversine Formula**. Jika > radius (misal 100m), tolak dengan `reason = out_of_radius`.
- **F-10**: Laravel mengirim *snapshot* ke ARSA API. Wajib mengembalikan `match_score >= 0.85` dan `liveness = true`. Jika gagal, tolak dengan `reason = face_mismatch` atau `liveness_failed`.
- **F-11**: Sistem memvalidasi jam absen masuk/pulang dengan jadwal divisi. Jika gagal, tolak dengan `reason = outside_schedule`.
- **F-12**: Jika lolos semua validasi, **Watermark** dibuat server-side menggunakan Intervention Image.
- **F-13**: Watermark berisi: Nama, NIK, Divisi, **Waktu Server (`now()`)**, Latitude, Longitude, dan Jarak ke SPPG (meter).
- **F-14**: Simpan foto ke storage, simpan data ke tabel `attendances`, dan catat log sukses/gagal ke `attendance_logs`.

### 5.5 Modul Izin / Sakit / Cuti
- **F-15**: Relawan mengunggah surat izin (foto/PDF) dan mengisi tanggal mulai/selesai.
- **F-16**: Admin dapat menyetujui (Approve) atau menolak (Reject).
- **F-17**: Izin yang disetujui tidak dihitung alpha dan tidak memotong honor di sistem payroll.

### 5.6 Payroll (Rekap Honor)
- **F-18**: Admin menentukan Skema Honor (Tarif/jam, Uang Transport harian, Uang Makan, Tarif Lembur, Potongan).
- **F-19**: Admin klik "Generate Payroll" untuk periode tertentu. Sistem mengkalkulasi total jam dari `attendances` dan `leave_requests`.
- **F-20**: Super Admin menyetujui (Approve) payroll yang sudah dibuat.
- **F-21**: Sistem menghasilkan **Slip Gaji PDF** (DomPDF) per relawan yang bisa diunduh.
- **F-22**: Admin dapat mengekspor rekap transfer ke Excel (Laravel Excel).

### 5.7 Notifikasi WhatsApp (Fonnte API)
- **F-23**: **Pengingat Absen:** Dikirim H-15 menit sebelum jam masuk divisi berakhir.
- **F-24**: **Info Slip Gaji:** Dikirim saat Payroll di-*Approve* (berisi total honor dan **Link URL** ke PDF).
- **F-25**: **Alert Admin:** Dikirim jika relawan gagal verifikasi wajah 3x berturut-turut atau indikasi IP address dipakai oleh >2 relawan dalam 3 menit.

## 8. Rancangan Database (Skema Inti)

**1. Tabel `users`**
*   `id`, `name`, `nik`, `email`, `password`, `phone`, `role` (Enum: super_admin, admin, relawan), `division_id`, `face_id`, `is_active`.

**2. Tabel `divisions` & `work_schedules`**
*   `divisions`: `id`, `name`.
*   `work_schedules`: `id`, `division_id`, `day_of_week`, `check_in_start`, `check_in_end`, `check_out_start`, `check_out_end`, `late_tolerance`.

**3. Tabel `attendances`**
*   `id`, `user_id`, `date`, `check_in_at`, `check_out_at`, `check_in_lat`, `check_in_lng`, `check_out_lat`, `check_out_lng`, `distance_m`, `photo_check_in_path`, `photo_check_out_path`, `total_hours`.

**4. Tabel `attendance_logs`**
*   `id`, `user_id`, `type` (in/out), `status` (success/failed), `reason` (out_of_radius, face_mismatch, etc), `ip_address`, `user_agent`.

**5. Tabel `leave_requests`**
*   `id`, `user_id`, `type` (izin/sakit/cuti), `start_date`, `end_date`, `attachment_path`, `status` (pending/approved/rejected), `reviewed_by`.

**6. Tabel `payrolls` & `payroll_details`**
*   `payrolls`: `id`, `period_start`, `period_end`, `status` (draft/approved/paid).
*   `payroll_details`: `id`, `payroll_id`, `user_id`, `total_hours`, `net_salary`, `payment_status`.

## 9. Alur Kerja (Sequence) Proses Absensi

1. Relawan menekan tombol "Absen Masuk" di browser.
2. Browser meminta izin Kamera dan Lokasi (GPS).
3. Browser mengirim data `{ foto_base64, lat, lng }` ke API Laravel.
4. Laravel memvalidasi **Haversine**. Jika > 100m, tolak dan simpan log.
5. Laravel mengirim foto ke **ARSA API**. Jika skor < 0.85 atau liveness false, tolak dan simpan log.
6. Laravel mengecek **Jadwal Divisi**. Jika di luar jam, tolak dan simpan log.
7. Jika lolos, Laravel menggunakan **Intervention Image** untuk mencetak teks (Timestamp & GPS) ke foto.
8. Foto disimpan di `storage/app/public/absensi/`.
9. Laravel menyimpan record ke tabel `attendances`.
10. Laravel mengirim request ke **Fonnte API** (Notif WA).
11. Response sukses dikirim ke browser, halaman menampilkan foto berwatermark.

## 10. Strategi Pengujian (Untuk Sempro)

| Fitur | Metode Uji | Indikator Keberhasilan |
| :--- | :--- | :--- |
| **Wajah** | Uji dengan wajah asli vs foto cetak/layar HP | Foto palsu ditolak dengan status `liveness_failed`. |
| **GPS** | Uji absen di dalam dan luar radius 100m | Luar radius ditolak, log mencatat jarak (misal: 250m). |
| **Watermark** | Cek file foto di direktori storage | Teks timestamp server & koordinat tercetak jelas dan tidak bisa diedit. |
| **WA API** | Kirim pesan uji ke nomor HP penguji | Pesan masuk ke WhatsApp dengan format benar. |
| **Payroll** | Generate gaji 1 bulan untuk 5 relawan | Angka jam kerja, uang makan, dan total bersih sesuai rumus. |

## 11. Mitigasi Risiko & Batasan (Shared Hosting)

| Risiko | Dampak | Solusi |
| :--- | :--- | :--- |
| **Kuota ARSA (100/bln) Habis** | Tidak bisa demo wajah saat sidang. | Gunakan `FACE_API_MODE=dummy` di file `.env` saat masa *coding/testing*. Ganti ke asli H-1 sebelum sidang. |
| **Hostinger Timeout** | Gagal upload foto kamera besar. | Set `max_execution_time`=120 dan `upload_max_filesize`=10M di menu PHP Config hPanel. |
| **GPS Tidak Akurat** | Relawan dalam gedung gagal absen. | Set radius default ke 100m (bisa diubah Super Admin). |
